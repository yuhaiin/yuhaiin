# Hysteria 2 throughput and interoperability — 2026-10-07

The native client/server adapters pass bidirectional interoperability with official Hysteria 2.13.0, including certificate verification against the persisted TLS-auto CA and Salamander. The 200 Mbps configuration behaves like the official baseline. Default 16 KiB relay buffers reduce native-server single-stream download throughput on this host; selecting the existing 32 KiB advanced setting removes the measured gap.

## Conditions

- AMD Ryzen 5 5600G; Linux amd64; independent target, server and client processes over IPv4 loopback; `GOMAXPROCS=4` per process.
- Native Go 1.27.1 (`X:nodwarf5`); official binary Go 1.26.8, Hysteria app/v2.13.0, commit `ca8fbd8`. Both use apernet/quic-go revision `a10df75c260c`. Different compiler versions and the official local-forward adapter limit direct attribution of differences.
- Three repetitions per workload; medians below. Each TCP measurement verifies 128 MiB total payload, split equally for four streams; timing starts after connection creation. Fresh client process/QUIC connection per measurement.
- UDP echo sends 40,000 packets of 1,000 bytes at 20,000 packets/s (160 Mbps offered), followed by one second for delayed replies. Sequence numbers and payload checks detect loss and corruption.
- Native server uses the actual inbound handler, NAT and direct outbound, with default 16 KiB relay buffers. TLS-auto state is saved through the inbound store and reused on server restart. No concurrent builds/tests ran during measurements.

These measurements describe local CPU and relay overhead. They do not predict remote RTT, lossy-path performance, or Internet link capacity. TCP transfers are short at several Gbps, so small differences should not be treated as precise rankings.

## UDP integrity

Across all eight scenarios and three repetitions, all **960,000** packets returned: **0 lost, 0 corrupt**. Median receive throughput was approximately 159.98–159.99 Mbps at the 160 Mbps offered load. This demonstrates forwarding at that load, rather than the maximum achievable UDP rate. Native/native integration tests separately verify 8 KiB fragmented messages and independent UDP sessions; the official interoperability load uses 1,000-byte payloads.

## Existing relay buffer setting

A separate three-repetition BBR matrix changed only native-server relay buffers to 32 KiB. It used the same 128 MiB TCP workloads and shortened UDP workloads to 4,000 packets.

| Client | Native server, 16 KiB, single download | Native server, 32 KiB, single download | Official server, same 32 KiB diagnostic run |
|---|---:|---:|---:|
| native | 3062.2 | 4268.7 | 4124.1 |
| official | 2865.5 | 3968.5 | 4020.8 |

The controlled buffer change strongly supports the existing relay write size as the source of the single-stream gap. To select the measured setting, use `advanced.relayBufferSize: 32768` in the existing settings API. This affects the shared relay mechanism; this PR preserves the existing 16 KiB default.

## Reproduce

```sh
python scripts/bench/hysteria2/run.py \
  --official /absolute/path/to/hysteria-linux-amd64 \
  --output /tmp/hysteria2-default.json
python scripts/bench/hysteria2/run.py \
  --official /absolute/path/to/hysteria-linux-amd64 \
  --scenario bbr --relay-buffer-size 32768 --udp-packets 4000 \
  --output /tmp/hysteria2-buffer32.json
```
